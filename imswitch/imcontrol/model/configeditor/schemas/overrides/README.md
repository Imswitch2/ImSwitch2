# Hand-written schema overrides

Everything else under `schemas/` is generated by
`python tools/extract_manager_schemas.py --write` and must not be edited by
hand. This directory is the opposite: written by people, never by the tool,
merged **last** so it wins.

Why it exists: the generator emits a validation `type` only where the manager's
code *proves* one (`Path(...)`, a nested subscript, `.items()`). A default
literal or an `int()` call says what the manager prefers, not what it accepts,
so most properties are generated without a `type` and accept anything. When
you have read the manager and know the accepted set, say so here.

One file per manager, `<ManagerName>.json`, with any of:

```json
{
  "description": "replaces the schema's description",
  "properties": {
    "key": {"type": ["string", "null"], "enum": [...], "description": "..."}
  },
  "required": ["keyThatIsRequiredAfterAll"],
  "optional": ["keyTheCodeReadsUnguardedButToleratesMissing"]
}
```

`properties` deep-merges per key (a new key creates the property); `required`
adds, `optional` removes. Every property touched gets `"override"` in its
`x-imswitch-source`. Any other top-level key is refused, so a typo cannot be
silently ignored. Regenerate after editing so the merged schema is checked in.
