# Config editor: discovery, schema and validation (open tail)

**Status (2026-10-17):** The catalog, schema/default builder, plugin templates and
the shared validation service shipped (`imswitch/imcontrol/model/configeditor/`:
`catalog.py`, `schemas.py`, `defaults.py`, `templates.py`, `resources.py`,
`extraction.py`, generated `schemas/` package data; `model/plugins/validation.py`
with `SetupDiagnostic`, `SetupFix`, `ValidationContext`, xref and DAQ checks).
The editor itself is now the package `imswitch/imcontrol/view/configeditor/`
(the old 4,100-line `utility_scripts` script is a 25-line launcher). Schemas for
core managers are generated by `tools/extract_manager_schemas.py`, which replaced
the hand-maintained "registry contribution with schema" route this plan assumed.

What remains (verified against the tree):

1. **CLI vs editor validation parity.** `python -m imswitch.imcontrol.model.plugins
   validate-setup` calls `validate_setup_file(path, registry)` with **no
   `ValidationContext`** (`plugins/__main__.py:150`), while the editor supplies
   widget-to-section requirements and the known ImProcess reconstructor/processor
   ids (`view/configeditor/editor.py:773`, `_WIDGET_REQUIRES_SECTION`). The CLI
   therefore silently emits a weaker report (no `widget.missing-section`, no
   ImProcess id checks). Fix: move the requirements and id providers into a
   Qt-free factory in the model layer, use it from both, and add a paired test
   that validates one fixture through the model, the CLI and the editor adapter
   and asserts equal diagnostic codes.
2. **Resource and template split.** Editor overlays and blank forms still live in
   `imswitch/imcontrol/view/configeditor/builtin_templates/` (shipped via
   `MANIFEST.in` graft) and `TemplateStore` (user templates) still lives in
   `view/configeditor/editor.py:3316`. Move both behind a Qt-free model service
   (`importlib.resources`, injectable root) so non-Qt tests cover a malformed
   resource, a blank schema and a user-template round trip.
3. **Schema-driven editing.** Optional `x-imswitch-*` UI annotations (group,
   label, help, units, path picker, secret masking, device-reference category)
   and lossless round-tripping of unknown nested members for plugin schemas;
   a plugin with only manifest + JSON Schema should be editable with no core
   resource file. (`x-imswitch-kind`/`-nullable` already exist for type
   fidelity; the UI annotations do not.)
4. **UX on the settled contract (Phase 6).** Manager detail panel (source,
   version, aliases, docs URL, schema status), pre-save compatibility report
   (legacy-scanned managers, retained unknown fields, unavailable plugins), and
   quick fixes only for diagnostics that carry a `SetupFix`. "Create from
   connected hardware" only for managers that declare a side-effect-free
   discovery capability; never infer it by importing a manager class.

Safeguards that still apply: preserve unknown sections, aliases and unknown
values on save; never use manager-class introspection for metadata; land each
item with unit tests plus one offscreen Qt smoke test.
