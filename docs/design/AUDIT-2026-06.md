# ImSwitch2 structural audit — June 2026

**Method.** Six read-only audits were run in parallel (OpenHands, isolated to
`/tmp` reports, no repo writes) across distinct angles, then synthesized and
**spot-verified against the code** by the reviewing agent. The raw per-angle
reports are in [`audit-2026-06/`](audit-2026-06/). Confidence markers below:
✅ verified against code · ⚠️ raw-report claim corrected during review · ◽
plausible but unverified.

> The synthesis deliberately discards several raw-report claims that turned out
> to be wrong or fabricated (see "Corrections" at the end). Treat the raw reports
> as evidence, not gospel.

## TL;DR

ImSwitch2 is a **mid-migration "transition architecture"**: several well-designed
new abstractions (state-persistence, smart-modes, device-plugins, shortcuts)
coexist with **live legacy escape hatches**, and a handful of module/layer
boundaries have eroded. Nothing is broken, but the seams are where bugs and
confusion will accumulate. The most concrete weak points are in **release/test
hygiene** (a dependency range and a schema-tolerance bug that both undermine the
test suite) and **hardware error-handling**. Docs meaningfully lag the code.

  scripting/API automation audit. It finds that script cancellation uses
  `QThread.terminate()` while stdout/stderr are globally redirected, remote

  remote server/API audit. It finds that the optional server blocks in

- [`14-device-plugin-registry.md`](audit-2026-06/14-device-plugin-registry.md):
  device plugin registry audit. It finds that registry-first resolution can
  shadow unlisted in-tree managers, discovery/collision diagnostics are dropped,
  and the public plugin API does not cover every registry-backed kind. Since the
  audit, microscope stands have moved to registry-backed resolution; the pulse
  generator remains the unsupported manifest kind.

## Structural themes

### A. The legacy→new migration is incomplete (the dominant "doesn't fit" story)
*(report 03, corroborated by 04)*
- **Live dual mode-switching**: `sigSetConfig`/`sigSetVisibleLayers` still emitted
  by EtSnouty (`:273,274,290`) and consumed by `SetupStatusController`
  (`:91,195,197`) ✅. SetupStatus also carries hardcoded COM ports + dead code
  (`SetupStatusController.py:17`) ✅. Two audits independently flag SetupStatus →
  clear decommission target (aligns with the smart-microscopy plan).
- **EtSnouty diverges** from `EventTriggeredControllerBase` while EtSTED/EtMonalisa
  inherit it ✅.
- **Real state-persistence gap is the *scan* controllers** (TriggerScope ×4 +
  LightSheetMulticolor lack `StatefulComponentMixin`) ✅ — *not* the headline
  "32 controllers untyped" (most of those are UI-only and correctly stateless ⚠️).

### B. Layering / encapsulation erosion at module seams *(report 02 — all ✅)*
- Model→controller imports: `NidaqLaserManager.py:6` imports
  `CommunicationChannel`; `WidgetStatePersistence.py:210` imports
  `ComponentStateApplyMode` from `basecontrollers`.
- Follow-up static audit confirms the same direction problem in workflow types:
  `smart_mode_workflow.py:35` references controller-owned smart-mode service
  contracts, and `TargetTimelapseWorkflow` consumes the adapter from that layer.
- Controller→view: `TilingController.py:249` imports `SegmentationParamsWidget`.
- **imcontrol ↔ improcess circular dependency** (fwd: `workflows/segmentation.py:38`;
  rev: `WatcherFrame.py:3`, `ImProcessMainController.py:54/232`,
  `processing_config.py:9-10`) — improcess cannot stand alone.
- Controllers reach manager internals: `._subManager`/`._subManagers` (EtMonalisa,
  EtSnouty), `._position` (`BSC203Controller.py:147`), `._laserInfo`
  (`LaserController.py:37`) — missing public manager APIs. The follow-up audit
  adds `StandManager`, detector access, position tracking, and laser calibration
  metadata as concrete API gaps.

### C. Safety-relevant error handling *(reports 04 + 06)*
Bare-`except` swallowing in hardware/DAQ paths, plus **untested safety-critical
managers** (Nidaq/TriggerScope laser & positioner managers control power/motion
via DAQ and have zero tests) ✅.

### D. Packaging *(report 05)*
napari floor (above), stale wheel (above), `setuptools<80` cap (LOW). ⚠️ Three of
this report's claims were **wrong** and discarded: nidaqmx is *already* a
`[hardware]` extra (`setup.cfg:54`), numpy *is* pinned (`numpy>=1.21`, loosely),
and `microscope` almost certainly *does* exist on PyPI (python-microscope).

### E. Test trust *(report 06)*
Schema-tolerance collection bug + CI masking (below); low coverage of
`BeadRecController` and safety-critical managers ✅; brittle `inspect.getsource()`
contract tests (5 files — *some from recent in-house work*) ✅. ⚠️ Its
"`EventTriggeredBaseController` untested" finding was **discarded**: it cited four
fabricated method names and the base *is* exercised via a stub in
`test_event_triggered_smart_modes.py`.

### F. Docs drift *(report 01)*
`ARCHITECTURE.md` lists 28 widgets / 18 controllers vs **48 / 46** actual ✅;
stale `imreconstruct`/`imnotebook` refs in `shortcuts_config.md` ✅; the README
"one file + one JSON entry" claim holds only for *managers* (controllers/widgets
need manual `__init__.py` registration) ✅; a contradictory "SLMController removed"
milestone while the class still exists ✅.

### G. Workflow production-readiness *(follow-up 09)*
The model workflow direction is broadly right, but `TilingWorkflow` currently
restores laser mode and closes HDF5 files only on the successful path. Before
tiling becomes the foundation for mode-switched timelapse and event-gated
acquisition, it needs failure-path cleanup guards, cancellation, and typed
workflow contracts.

### H. Registration/setup/lifecycle drift *(follow-up 10)*
The device-manager registry is ahead of the UI registry. Widgets/controllers are
still loaded through static maps and class-name conventions, and those maps are
already stale for `WellPlate`/`Et`. Setup parsing does not catch stale
`availableWidgets` keys, and the optional server/threaded manager lifecycle
needs explicit start/stop/finalize contracts.

### I. ImProcess plugin architecture is still in-tree only *(follow-up 11)*
ImProcess has a useful registry contract, but the concrete plugin list is still
hardcoded in built-in dictionaries. Unknown explicit plugin IDs are filtered
away instead of diagnosed, and the generic reconstructor manager still
special-cases `monalisa` and `widefield-starss` by id.

### J. Scripting/API automation is powerful but not lifecycle-safe *(follow-up 12)*
The scripting surface is a trusted local automation feature, but it currently
uses unsafe thread termination, process-wide output redirection, raw controller
access, and unstructured completion signals. That is too loose for unattended
smart-microscopy workflows unless scripts get cooperative cancellation and
job-level status/error/result contracts.

### K. Remote server/API control is not yet a stable automation boundary *(follow-up 13)*
The optional server path is dormant by default, but enabling it exposes a
half-wired FastAPI/Pyro hybrid. The deeper architectural issue is that the API
contract lacks namespacing, return/error propagation for UI-thread calls,
authorization, and capability policy. That should be fixed before remote smart
microscopy workflows depend on it.

### L. Device plugins are usable but the extension contract is incomplete *(follow-up 14)*
The device plugin registry is one of the cleaner new abstractions, but its
runtime behavior is still narrower than the public contract. Registry-backed
resolution now covers the MultiManager device families plus microscope stands,
and flip-mirror/stand compatibility aliases are protected as built-ins. The
pulse generator is still a future manifest kind, and plugin diagnostics plus
public API coverage need tightening before broad third-party hardware
extraction.

## Newly discovered: SetupInfo schema fragility (root cause of the collection bug)

Several `SetupInfo` sub-dataclasses declare `Optional[...]` (or plain) fields
**without defaults**, so any bundled setup that omits them fails
`dataclasses_json` deserialization with `KeyError`. The module-level loader in
`test_example_setups.py` aborts on the first failure, which is why report 06's
clean env only surfaced `maxScanTimeMin` — fixing it exposes the next
(`serial_number`, then `analogChannel`, then `swapImageAxes`, ...).

- **Fixed**: `ScanInfo.maxScanTimeMin`/`lineClockLine`/`frameStart|EndClockLine`,
  `SLMInfo.serial_number`, `SLMsInfo.{nSections,widgetOptions,serial_number}` —
  defaulted to `None` (optionals reordered to class end; verified no positional
  construction, so name-based deserialization is unaffected).
- **Fixed next**: `DeviceInfo.{analogChannel,digitalLine,managerProperties}` now
  default to `None`/`{}` and the `DeviceInfo` hierarchy is keyword-only to avoid
  dataclass inheritance ordering traps. `FocusLockInfo.swapImageAxes` defaults to
  `False`. A unit-level bundled setup schema test now parses every example setup,
  and `test_example_setups.py` is no longer ignored in the manual multi-OS
  workflow.

`test_example_setups.py` collection is unblocked locally; remaining failures in
that UI test, if any, are now actual startup/UI issues rather than schema
deserialization blockers.

## Suggested sequencing
1. Decommission `SetupStatus`/`sigSetConfig` once external Snouty setup migrates
   (smart-microscopy plan) → closes the biggest live-legacy seam.
2. Add public manager APIs for `StandManager`, named detector access, position
   tracking, and laser calibration/display metadata; then refactor the private
   reaches.
3. Continue protecting in-tree registry-backed manager names and aliases in the
   device plugin registry, then surface discovery/collision/schema diagnostics
   before extracting more device families.
4. Replace or explicitly disable the optional server path until it has one
   supported protocol, deterministic start/stop, authorization/capability
   policy, and UI-thread API return/error propagation.
5. Add a common finalization contract for bespoke managers with threads.
6. Add structural setup validation for widget/controller/layout keys and fix the
   stale bundled setup entries (`example_sted` `Rotation`, default
   `WellPlate`/`Et` registration drift).
7. Remove the hardcoded external script path, then replace script
   `QThread.terminate()` with cooperative cancellation and structured
   job/error/result signals before building unattended workflows on scripting.
8. Remove manager-level hardcoded serial-port defaults and finish replacing the
   remaining bare exception handlers called out in the follow-up audit.
9. Add cleanup guards to `TilingWorkflow` before promoting tiling + modes +
   event-triggered acquisition as production workflow infrastructure.
10. Break imcontrol↔improcess cycle (move shared segmentation/algorithms to
   `imcommon`; invert the improcess→imcontrol edges via injection).
11. Move state/mode protocol types out of controller modules, then remove easy
   mutable defaults and unused cross-layer imports.
12. Replace controller readiness sleeps with manager/workflow readiness signals
   or cancellable workflow runtime primitives.
13. Make ImProcess processing plugin config strict, then move MoNaLISA and
    widefield-specific actions behind plugin-declared capabilities.
14. Extract scan/setup controller services (`ScanControllerAdvanced`,
   `SetupModesController`) once they can depend on stable manager contracts.
15. Refresh `ARCHITECTURE.md` inventories + fix stale module names in docs.
16. Backfill tests for safety-critical DAQ/laser/stage managers + `BeadRecController`.
