Scripting API reference
=======================

Everything a script can call, by the widget that provides it: a function
exists only while its widget is loaded (``availableWidgets`` in the setup
file, see :doc:`imcontrol-setups`), and ``api.imcontrol`` raises
``AttributeError`` for the others. Every function returns its value, or
raises its exception, in the script; the ones that drive the GUI run on
the GUI thread and block the script until they have run (see
:doc:`scripting` for the threading model, waiting for signals and the
tutorials). Names of devices are the ones the setup file gives them --
``getDetectorNames()``, ``getLaserNames()``, ``getPositionerNames()`` and
``getRotatorNames()`` list them.

Cameras and detectors
---------------------

*Widget:* ``Settings``. Detector names, their parameters (exposure, trigger source, ROI, binning -- whatever the Settings widget shows for the detector) and the size of their pixels in the sample.

.. py:function:: api.imcontrol.getDetectorNames()
   :no-index:

   Returns the device names of all detectors. These device names can
   be passed to other detector-related functions.

.. py:function:: api.imcontrol.getDetectorParameter(detectorName: str, parameterName: str)
   :no-index:

   Returns the value of the specified detector-specific parameter, in
   the parameter's own units -- the value the Settings widget shows.
   Parameter names and units differ from detector to detector;
   getDetectorParameters lists them. Raises AttributeError for a name
   the detector does not have.

.. py:function:: api.imcontrol.getDetectorParameters(detectorName: str)
   :no-index:

   Returns all detector-specific parameters of the specified detector
   as {parameter name: {'value', 'units', 'editable', 'options'}}. 'units'
   is None for a parameter that picks from a list of 'options', and
   'options' is None for a numerical one. Only an editable parameter can
   be changed with setDetectorParameter.

.. py:function:: api.imcontrol.getDetectorPixelSize(detectorName: str)
   :no-index:

   Returns the size of the detector's pixels in the sample, in µm,
   as ``[Z, Y, X]``: for a camera its pixel size setting, for a
   scan-driven detector (APD, PMT, ...) the scan's step. ``Z`` is 1
   when nothing steps it.

.. py:function:: api.imcontrol.setDetectorBinning(detectorName: str, binning: int)
   :no-index:

   Sets binning value for the specified detector.

.. py:function:: api.imcontrol.setDetectorROI(detectorName: str, frameStart: Tuple[int, int], shape: Tuple[int, int])
   :no-index:

   Sets the ROI for the specified detector. frameStart is a tuple
   (x0, y0) and shape is a tuple (width, height).

.. py:function:: api.imcontrol.setDetectorParameter(detectorName: str, parameterName: str, value: Any)
   :no-index:

   Sets the specified detector-specific parameter to the specified
   value.

The live view
-------------

*Widget:* ``View``. Which detectors the image view shows, the live view itself, and the newest frame as an array.

.. py:function:: api.imcontrol.setDetectorSelected(detectorName: str, selected: bool)
   :no-index:

   Select or deselect a detector for ImSwitch-managed acquisition.

   Deselected detectors are left out of live view and of scans. A
   detector an explicit consumer is holding — a recording, a workflow, an
   event modality — still runs regardless, so this cannot silently break
   an acquisition already under way.

   Returns False when the change is queued because a scan currently owns
   the detector; it is applied at the next scan iteration.

.. py:function:: api.imcontrol.getSelectedDetectors()
   :no-index:

   Names of the detectors currently selected for acquisition.

.. py:function:: api.imcontrol.setLiveViewActive(active: bool)
   :no-index:

   Sets whether the LiveView is active and updating.

.. py:function:: api.imcontrol.getLatestFrame(detectorName: Optional[str] = None)
   :no-index:

   Returns the newest frame of a detector as a NumPy array
   ``(rows, columns)`` -- what the live view shows -- without a snap or
   a file. ``None`` means the current detector. The detector has to be
   acquiring, with the live view on (setLiveViewActive) or a recording
   running, for the frame to be new.

Snaps and recordings
--------------------

*Widget:* ``Recording``. Snaps into numpy or to a file; recordings to a file in every mode of the Recording widget, and recordings to memory that return their frames as an array. A recording to a file ends with the ``recordingEnded`` signal (``recordingFailed`` when it fails); the memory variants wait themselves.

.. py:function:: api.imcontrol.getFileName()
   :no-index:

   Gets the filename of the data to save.

.. py:function:: api.imcontrol.snapImage(output: bool = False)
   :no-index:

   Take a snap and save it to a .tiff file at the set file path.

.. py:function:: api.imcontrol.startRecording()
   :no-index:

   Starts recording with the set settings to the set file path.

.. py:function:: api.imcontrol.isRecording()
   :no-index:

   Whether a recording is currently active.

.. py:function:: api.imcontrol.stopRecording()
   :no-index:

   Stops recording. Idempotent: returns True if a recording was
   active and its stop was requested (``recordingEnded`` or
   ``recordingFailed`` will follow), False if nothing was recording (no
   signal will follow, so do not wait for one).

.. py:function:: api.imcontrol.recordScanToMemory(detectorName: Union[List[str], str, int, NoneType] = None, timeout: float = 600.0, keep: bool = False)
   :no-index:

   Runs the scan the Scan widget holds once and returns the frames
   it triggers as a NumPy array ``(frames, rows, columns)``, without
   writing a file: the recording goes to memory, is read back, and is
   dropped. With several detectors the result is a dict that maps each
   detector's name to its array.

   ``detectorName`` is a detector's name, a list of names, ``-1`` for
   the current detector, ``-2`` for all of them, or None for what the
   Recording widget has selected. The call blocks until the scan and
   the recording are over, at most ``timeout`` seconds; it raises
   ``RuntimeError`` when the recording is refused or fails and
   ``TimeoutError`` when it does not finish (the recording is stopped).
   The Recording widget's settings are put back afterwards. With
   ``keep=True`` the recording also stays listed in ImProcess, as a
   recording to RAM does. It runs on the caller's thread, which must
   not be the GUI thread (a script's is not).

.. py:function:: api.imcontrol.recordFramesToMemory(detectorName: Union[List[str], str, int, NoneType], numFrames: int, timeout: float = 600.0, keep: bool = False)
   :no-index:

   Records ``numFrames`` frames of a detector, as the Recording
   widget's *Number of frames* does, and returns them as a NumPy array
   ``(frames, rows, columns)`` without writing a file. Everything else
   is as for recordScanToMemory: ``detectorName`` (a name, a list, -1,
   -2 or None), the result for several detectors, ``timeout``,
   ``keep`` and the errors.

.. py:function:: api.imcontrol.setRecModeSpecFrames(numFrames: int)

.. py:function:: api.imcontrol.setRecModeSpecTime(secondsToRec: Union[int, float])
   :no-index:

.. py:function:: api.imcontrol.setRecModeCameraTimelapse(framesToRec: int, intervalSeconds: Union[int, float], timelapseSingleFile: bool = False)
   :no-index:

   Configure a camera-only timelapse of discrete one-frame captures.

.. py:function:: api.imcontrol.setRecModeScanOnce()
   :no-index:

   Sets the recording mode to record a single scan.

.. py:function:: api.imcontrol.setRecModeScanTimelapse(lapsesToRec: int, freqSeconds: float, timelapseSingleFile: bool = False)
   :no-index:

   Sets the recording mode to record a timelapse of scans.

.. py:function:: api.imcontrol.setRecModeUntilStop()

.. py:function:: api.imcontrol.setDetectorToRecord(detectorName: Union[List[str], str, int], multiDetectorSingleFile: bool = False)

Scans
-----

*Widget:* ``Scan``. The scan the Scan widget holds: its settings as a file or a dict, running it with an exact completion (see *Threading model* in :doc:`scripting`), and the two fields a script changes most. The TriggerScope raster widget exports the same ``saveScanParamsToFile`` and ``loadScanParamsFromFile``.

.. py:function:: api.imcontrol.saveScanParamsToFile(filePath: str)
   :no-index:

   Saves the set scanning parameters to the specified file.

.. py:function:: api.imcontrol.loadScanParamsFromFile(filePath: str)
   :no-index:

   Loads scanning parameters from the specified file.

.. py:function:: api.imcontrol.getScanParameters()
   :no-index:

   Returns the scan the Scan widget holds as a dict, the same
   content saveScanParamsToFile writes: ``analogParameterDict`` (the

.. py:function:: api.imcontrol.setScanParameters(parameters: dict)
   :no-index:

   Puts a dict from getScanParameters, edited or not, into the Scan
   widget, as loadScanParamsFromFile does with a file. Raises
   ValueError, naming what could not be applied, when the dict does
   not fit the setup (a device the setup lacks, say).

.. py:function:: api.imcontrol.changeScanCenterPos(positionerName, positionerScanCenterPos)
   :no-index:

   Sets the centre of the scan along a positioner, in µm (the Scan
   widget's *Center*).

.. py:function:: api.imcontrol.changeScanSize(positioner: str, size: float)
   :no-index:

   Sets the size of the scan along a positioner, in µm (the Scan
   widget's *Size*).

.. py:function:: api.imcontrol.changed3StepDelayPar(d3StepDelay)
   :no-index:

   Sets the Point scan widget's delay before each step of the third
   axis.

.. py:function:: api.imcontrol.runScan(source: Optional[str] = None)
   :no-index:

   Starts one scan with the parameters set in the scan widget and
   returns a handle for its completion.

   The request is pre-flighted before any lifecycle signal is published;
   a refused start (a scan is already running, the previous one is still
   finishing, ...) raises ``ScanRequestRejectedError`` (a RuntimeError)
   whose message is the reason, and nothing else happens. A scan design
   the scan manager refuses (longer than ``scan.maxScanTimeMin``, a
   scanner driven outside its voltage range) raises the same way; it is
   found only after ``scanStarting`` went out, which is then paired with
   a ``scanEnded``. On rigs with several scanners ``source``
   selects one by its widget key (see getScanSourceNames); without it the
   canonical Scan controller or a lone capable controller is used, and
   ambiguity raises. Repeat is switched off for the scan.

   The returned handle resolves for exactly this scan whatever the order
   of any waiter: ``handle.wait(timeout)`` (from a script), ``handle.done``
   / ``handle.successful`` / ``handle.message``, or
   ``getScanRequestStatus(handle.requestId)`` (remote clients receive the
   handle as ``{requestId, source, state, message}``).

.. py:function:: api.imcontrol.getScanSourceNames()
   :no-index:

   Widget keys of every scan controller that runScan(source=...) can
   target on this setup.

.. py:function:: api.imcontrol.getScanRequestStatus(requestId: str)
   :no-index:

   Status of a scan started with runScan, as ``{requestId, source,
   state, message, exact}`` with state ``pending``, ``succeeded`` or
   ``failed``. Raises KeyError for an unknown or evicted request id.

.. py:function:: api.imcontrol.buildWorkflowFacade(**kwargs: Any)
   :no-index:

   Build a MicroscopeFacade from the current master controller.

   ImSwitch's ``generateAPI`` flattens every ``@APIExport``'d method to
   the top level of ``api.imcontrol`` — so this method is reachable as
   ``api.imcontrol.buildWorkflowFacade(...)`` (not via a sub-namespace).

   :param \*\*kwargs: Forwarded to ``build_facade_from_master``. Common arguments:

                      - ``laser_aliases`` (dict[str, str]): logical → setup laser names
                      - ``detector_name`` (str): name of detector/camera to expose
                      - ``xy_positioner_name`` (str): name of XY positioner
                      - ``z_positioner_name`` (str): name of Z positioner
                      - ``time_resolved_detector_name`` (str): detector implementing
                        the time-resolved contract
                      - ``hwp_name`` / ``qwp_name`` (str): rotator names
                      - ``hwp_presets`` / ``qwp_presets`` (RotatorPresets)
                      - ``scan_workflow`` / ``scan_done_signal``: optional overrides;
                        by default these are taken from the communication channel

   :returns: facade object with WFS-shaped sub-facades.
   :rtype: MicroscopeFacade

   .. rubric:: Example

   >>> facade = api.imcontrol.buildWorkflowFacade(
   ...     laser_aliases={'488': '488 (EXC) sn27311',
   ...                    '405': '405 (ACT) sn26647'},
   ...     detector_name='Kiralux',
   ...     xy_positioner_name='XY',
   ...     z_positioner_name='Z',
   ...     hwp_name='HWP', qwp_name='QWP',
   ... )
   >>> facade.laser_con.set_constant_power(['488'], [50.0])

Signals
-------

``api.imcontrol.signals()`` returns the events a script can wait for with
``getWaitForSignal`` and ``callAndWaitForSignal``:

- acquisitionStarted
- acquisitionStopped
- recordingStarted
- recordingEnded
- recordingFailed
- scanStarting (the run-level start, before hardware arms)
- scanStarted (the execution backend started the iteration)
- scanDone (an iteration finished)
- scanEnded (the run is over, on every terminal path)
- scanRejected(reason) (a start request was refused and its scan
  never runs; reason says why)

Script helpers
--------------

These are in every script's scope as bare names (``sleep(1)``, not
``api.sleep(1)``). They are the only waits that a press on *Stop* can
interrupt.

.. py:function:: importScript(path: str)

.. py:function:: getWaitForSignal(signal: imswitch.imcommon.framework.qt.Signal, pollIntervalSeconds: float = 0.05, timeout: Optional[float] = None)
   :no-index:

   Returns a function that will wait for the specified signal to emit.
   The returned function will wait until the signal has been emitted
   since its creation, so **create it before triggering the action** that
   emits the signal (e.g. before ``api.imcontrol.runScan()``); an
   emission that happened before creation is not seen.

   The returned function raises ``TimeoutError`` if ``timeout`` seconds
   pass without an emission (``None`` waits indefinitely) and
   ``OperationCancelled`` if the script is stopped. It accepts an
   optional ``timeout`` argument of its own that overrides the one given
   here. The polling interval defaults to 50 ms.

.. py:function:: callAndWaitForSignal(signal: imswitch.imcommon.framework.qt.Signal, func: Callable, *args, timeout: Optional[float] = None, **kwargs)
   :no-index:

   Creates a waiter for ``signal``, then calls ``func(*args,
   **kwargs)``, then waits for the signal. Returns what ``func``
   returned. This is the safe way to call an API function and wait for
   the event it causes, because the waiter exists before the call: a
   signal emitted synchronously inside the call is caught too.

   Example: ``callAndWaitForSignal(api.imcontrol.signals().recordingEnded,
   api.imcontrol.stopRecording, timeout=60)``. Raises ``TimeoutError``
   after ``timeout`` seconds and ``OperationCancelled`` if the script is
   stopped.

.. py:function:: runScanAndWait(timeout: Optional[float] = None, source: Optional[str] = None)
   :no-index:

   Starts one scan through ``api.imcontrol.runScan`` and waits for
   exactly that scan to end, whatever the timing of its signals. Raises
   ``RuntimeError`` if the start was refused (``ScanRequestRejectedError``)
   or the scan ended unsuccessfully, ``TimeoutError`` after ``timeout``
   seconds, and ``OperationCancelled`` immediately when the script is
   stopped (the running scan then finishes on its own). ``source`` picks
   the scan controller on rigs with several.

.. py:function:: sleep(seconds: float)
   :no-index:

   Sleeps for the specified number of seconds. Unlike ``time.sleep``,
   this returns immediately (raising ``OperationCancelled``) when the
   script is stopped.

.. py:function:: waitUntil(predicate: Callable[[], bool], timeout: Optional[float] = None, pollIntervalSeconds: float = 0.05)
   :no-index:

   Waits until ``predicate()`` returns a true value. Raises
   ``TimeoutError`` after ``timeout`` seconds (``None`` waits
   indefinitely) and ``OperationCancelled`` if the script is stopped.
